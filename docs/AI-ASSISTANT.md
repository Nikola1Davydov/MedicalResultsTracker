# ИИ-помощник: разбор вариантов

Это документ для обсуждения, а не описание готовой функции. В коде сейчас есть только
интерфейс `IAiAssistant`, механизм согласия `IAiConsentService` и заглушка
`DisabledAiAssistant`. Ни одной строки, которая обращается в сеть, в приложении нет.

## Исходное требование

1. Приложение полноценно работает **без** ИИ — значения вводятся руками.
2. ИИ подключается только по явному согласию.
3. ИИ решает две разные задачи: **ввод** (распознать бланк) и **толкование** (пояснить динамику).

Эти две задачи стоит разделять: у них разная цена ошибки и разный объём передаваемых данных.
Распознавание требует отправить весь документ — там ФИО, дата рождения, номер полиса, врач.
Пояснение требует отправить только числа.

## Вариант A. Без ИИ (то, что работает сейчас)

Ручной ввод, справочник показателей с подстановкой единиц и типовых норм, кнопка
«как в прошлый раз» — она копирует набор строк из предыдущего анализа, чтобы не
перенабирать панель заново.

Данные не покидают устройство вообще. Это базовая линия, и она рабочая: ввод панели
из 20 показателей — несколько минут один раз в полгода.

## Вариант B. Распознавание на устройстве

Android ML Kit Text Recognition / Apple Vision — оба бесплатны, работают офлайн,
дают текст с координатами блоков. Дальше нужен свой разбор: сгруппировать блоки в строки
по вертикали, вытащить из строки название / число / единицы / диапазон.

- **Плюс:** снимок никуда не уходит. Согласие формально даже не требуется — нечего согласовывать.
- **Минус:** разбор таблиц придётся писать самому, и он будет ломаться на нестандартных
  бланках (многоколоночная вёрстка, перенос названия на две строки, «норма» отдельной колонкой).
- **Реалистичная оценка:** 70–85 % строк заполнится верно, остальное пользователь правит руками.
  Для журнала анализов этого достаточно — проверять всё равно придётся.

Требует платформенного кода в `Platforms/Android` и `Platforms/iOS` за общим интерфейсом.

## Вариант C. Облачная модель со зрением

Отправка фото в мультимодальную модель, ответ — сразу структурированный JSON
(строгую схему можно задать через tool use / structured output). Качество на грязных
бланках заметно выше варианта B, писать разбор таблиц не нужно.

Проблемы, которые придётся решить:

- **Ключ API.** Зашивать ключ в мобильное приложение нельзя — его достают из пакета за
  пять минут. Варианты: пользователь вводит собственный ключ в настройках, либо появляется
  свой сервер-посредник. Второе противоречит идее «никакого бэкенда».
- **Медицинские данные третьей стороне.** Даже при отключённом обучении на данных
  документ уходит с устройства. Это должно быть отдельным, явным, отзываемым согласием —
  ровно то, что реализует `AiConsentScope.DocumentRecognition`.
- **Минимизация.** Перед отправкой стоит вырезать шапку с ФИО и номером полиса — хотя бы
  простым кадрированием, которое подтверждает пользователь.

## Вариант D. MCP

Стоит проговорить, чем MCP на самом деле является, потому что для мобильного приложения
он ложится не туда, где его обычно ожидают увидеть.

MCP — протокол, по которому **ИИ-клиент** (Claude Desktop, IDE, агент) получает доступ к
инструментам и данным. Он не является «способом позвать модель из приложения» — вызов
модели по-прежнему делает клиент, а не сервер.

Отсюда две принципиально разные конструкции:

**D1. Приложение как MCP-сервер.** Приложение (или маленький локальный сервис рядом с ним)
отдаёт наружу инструменты вида `list_tests`, `get_series(code)`, `export_csv`. Пользователь
подключает этот сервер к своему ИИ-клиенту и разговаривает о своих анализах там.

- Ключей в приложении нет. Приложение само никуда ничего не отправляет — оно только отвечает
  на запросы клиента, который запустил сам пользователь.
- Модель, провайдер и условия выбирает пользователь, а не автор приложения.
- Идеально ложится на задачу «толкование»: вопросы вида «что менялось с ферритином за два
  года» задаются в чате, где есть контекст и можно переспросить.
- Ограничение: на телефоне это работает плохо. MCP-клиенты живут на десктопе. Практический
  сценарий — десктопная сборка приложения (Windows/Mac Catalyst) либо экспорт истории
  в файл, который читает отдельный маленький MCP-сервер.

**D2. Приложение как MCP-клиент.** Приложение подключается к чужим MCP-серверам —
например, к серверу справочника лабораторных норм. Полезно, но задачу распознавания
бланка не решает.

Вывод: MCP — хороший ответ на «анализ значений», и он не отвечает на «распознать фото».
Это разные механизмы, и смешивать их в одну кнопку не нужно.

## Что предлагаю

| Задача | Решение | Почему |
|---|---|---|
| Ввод с бланка | Вариант B (на устройстве) | Данные не уходят, согласие не требуется, качества хватает для черновика |
| Толкование динамики | Вариант D1 (MCP-сервер) на десктопе | Ключ и провайдер — на стороне пользователя, приложение остаётся немым |
| Облачное распознавание | Вариант C как отдельная опция | Только со своим ключом и явным согласием, для тех, кому не хватило B |

Порядок работ: сначала B, потом D1, C — последним и, возможно, никогда.

## Правила, которые уже зашиты в код

1. **Ассистент возвращает черновик, а не запись.** `AiDraft` заполняет поля формы,
   в базу попадает только то, что пользователь просмотрел и сохранил. Такой анализ
   помечается `DataOrigin.AssistedReview` — потом видно, что вводилось не вручную.
2. **Согласие раздельное и отзываемое.** `AiConsentScope` — флаги: разрешить распознавание
   не значит разрешить отправку показателей на комментарий. Смена провайдера сбрасывает
   ранее выданные разрешения, потому что согласие даётся конкретному получателю данных.
3. **Согласие проверяется в сервисе, а не в UI.** `IAiAssistant.IsAvailable(scope)` — точка,
   мимо которой нельзя пройти, даже если кнопку случайно оставят активной.
4. **Никакой интерпретации без данных.** Если норма не указана, приложение показывает
   «норма не задана», а не выдумывает оценку. То же правило должно действовать и для ИИ.

## Что ещё нужно решить перед подключением

- Разрешение `android.permission.INTERNET` сейчас в манифесте есть по умолчанию. Пока
  сетевого кода нет, его можно убрать — тогда «ничего не отправляется» станет техническим
  фактом, а не обещанием. Вернуть его придётся вместе с вариантом C.
- Права на камеру не запрашиваются: `MediaPicker` вызывается только из сценария
  распознавания, который сейчас недоступен. При включении B/C нужно добавить `CAMERA`
  в манифест и `NSCameraUsageDescription` в `Info.plist`.
- Формулировка про врача. Приложение ведёт журнал и считает арифметику. Любой текст от
  модели — справочный; заключений и рекомендаций по лечению он давать не должен, и это
  ограничение стоит закладывать прямо в системный промпт.
