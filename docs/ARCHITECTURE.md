# Архитектура

## Главный принцип

Приложение — личный журнал результатов анализов. Оно работает целиком на устройстве
и остаётся полностью функциональным без интернета и без ИИ. Всё, что умеет помощник,
пользователь может сделать руками.

## Слои

```
View (XAML)  →  ViewModel (CommunityToolkit.Mvvm)  →  Services  →  SQLite (файл на устройстве)
```

| Слой | Где | За что отвечает |
|---|---|---|
| `Model` | `Model/` | Анализ, показатель, справочник, референсный диапазон, расчёт статуса |
| `Services/Database` | | Соединение с SQLite, репозиторий анализов, каталог показателей |
| `Services/Analysis` | | Сравнение с прошлым разом, ряды значений для графиков |
| `Services/Export` | | CSV (две формы) и JSON-бэкап, передача файла в системный «Поделиться» |
| `Services/Ai` | | Согласие пользователя и интерфейс помощника. Реализации с сетью нет |
| `Controls` | | Отрисовка графиков через `Microsoft.Maui.Graphics`, палитра статусов |

## Данные

Таблицы в одном файле `medical-results.db3` (`FileSystem.AppDataDirectory`):

- `blood_tests` — одна сдача анализа: дата, лаборатория, заметка, источник данных;
- `blood_parameters` — строки бланка: название, значение, единицы, границы нормы **этой** лаборатории;
- `analytes` — справочник показателей: типовые единицы и ориентировочные нормы для подстановки;
- `matrix_views` / `matrix_view_items` — свои наборы показателей для сводной таблицы (см. ниже).

Три решения, которые стоит помнить:

1. **Норма хранится вместе с результатом, а не только в справочнике.** У лабораторий
   границы отличаются, и через два года важно знать, с чем сравнивали тогда, а не сегодня.
2. **Значение может быть нечисловым.** `Value` — `double?`, рядом `TextValue` для
   «отрицательно», «следы», «< 0.5». В графики попадают только числа.
3. **Показатели сопоставляются между анализами по ключу** — `AnalyteCode.KeyOf`: код из
   справочника, а если его нет — код, выведенный из названия тем же правилом
   (`AnalyteCode.FromName`). От этого зависит, склеятся ли две сдачи в один график,
   поэтому правило намеренно живёт в одном месте: разойдись оно между «завести показатель»
   и «найти предыдущее значение» — и один показатель распался бы на два графика.

   Код проставляется при сохранении анализа (`TestEditViewModel.ResolveCodeAsync`): сначала
   уже проставленный, затем совпадение по названию в каталоге, и только потом новый код.
   Поэтому показатель, набранный руками, и он же, выбранный из справочника, — одна линия.

## Расширенная панель

Набор показателей нигде не фиксирован. Строки добавляются в любом количестве и с любыми
названиями; показатель, которого нет в справочнике, попадает туда автоматически в категорию
«Мои показатели» и в следующий раз подставляется сам.

В таблицах (CSV, текст для ИИ) строки — это объединение всех показателей за все анализы:
у сдач, где показателя не было, в его столбце пусто. Ни миграций, ни фиксированного набора
колонок — расширенная панель просто добавляет строки, а старые анализы остаются как есть.

Показатель ищется по названию (`SearchAsync`, восемь подсказок), а не выбирается из общего
списка: на семидесяти своих позициях список нечитаем.

Справочник правится на отдельном экране (настройки → справочник):

- **Скрыть, а не удалить** — встроенные записи удалять нельзя, удалённая вернулась бы при
  следующем запуске (`EnsureSeededAsync` досеивает недостающие). Флаг `IsHidden` убирает
  запись из подсказок, оставляя её в базе.
- **Удаление своей записи не трогает измерения.** Ключ графика — код, записанный в самом
  измерении; справочник лишь подставляет значения при вводе. Экран об этом прямо предупреждает.
- **Объединение дублей** (`ReassignCodeAsync`) переписывает код у всех измерений и убирает
  лишнюю запись. Это единственный способ склеить показатели, которые уже разъехались —
  например, если в двух лабораториях он назывался по-разному.

## Избранное и группы

И то, и другое — поля каталога (`Analyte.IsFavorite`, `Analyte.Category`), а не отдельные
таблицы. Измерения о них ничего не знают: перегруппировка не трогает историю и не требует
миграции, а сгруппировать можно и показатель, который сдавали один раз.

- **Избранное** — «слежу за этим постоянно». На главном экране идёт первым блоком и берётся
  **из всей истории**, а не из последнего анализа: витамин D сдают не каждый раз, но видеть
  его последнее значение и динамику хочется всегда. В динамике избранное собрано в группу
  `★ Избранное` — намеренно продублировано, оно остаётся и в своей предметной группе.
- **Группы** — свободный текст. Встроенная раскладка («Липиды», «Обмен железа») — только
  стартовая, её можно перекроить: у показателя выбирается существующая группа из списка
  либо вписывается новая. Выбор из списка нужен, чтобы рядом не завелись «Липиды» и «липиды».
- Показатели без группы собираются в «Без группы» и всегда идут последними.

## Одна дата — один столбец

Сводная таблица, CSV-выгрузка и текст для чата строятся из одной структуры
(`IAnalysisService.BuildMatrixAsync` → `ResultMatrix`), и столбец в ней — **календарная дата**,
а не отдельный бланк. Два соседних столбца с одинаковой шапкой ничего не сообщают:
если анализ сдан в один день, это один день.

Чтобы дубликаты не заводились в самой базе, новый анализ при сохранении дописывается
в уже существующий за то же число (`TestEditViewModel.MergeIntoAsync`):

- показателя там не было → добавляется молча;
- значение совпало → тоже молча, спрашивать не о чем;
- значение разошлось (другая лаборатория, вторая фотография) → один диалог со списком
  расхождений: заменить прежние значения новыми или оставить как было. Новые показатели
  добавляются в любом случае — отказ был про замену, а не про них.

Название второй лаборатории приписывается к первой через « · », а не затирает её.

Правка **уже сохранённого** анализа слияние не запускает: там пользователь работает
с конкретной записью, и подмешивать в неё соседнюю было бы неожиданно. Если такая пара
всё же осталась в базе, таблица сведёт её в один столбец при показе — внутри дня
более поздняя по `ModifiedUtc` запись перекрывает раннюю.

## Свои наборы в сводной таблице

Сводная таблица по умолчанию показывает **все** показатели за всю историю. Поверх неё
собираются свои подтаблицы: «вот это, это и это — один набор, а вот то — другой».

Наборы намеренно сделаны **отдельной сущностью**, а не ещё одним полем каталога. Группа
у показателя одна, а в наборы он входит в скольких угодно: холестерин нужен и в «сердце»,
и в «липидах». Поэтому связь многие-ко-многим — `matrix_views` плюс `matrix_view_items`.

- **Порядок строк задаёт сам набор.** `MatrixViewItem.SortOrder` хранит порядок, в котором
  человек ставил галочки: он выбирал не случайно, и в таблице строки идут так же.
  Режим «все показатели» сортирует по названию — другого осмысленного порядка там нет.
- **Набор ссылается на коды, а не на измерения.** Удаление набора не трогает историю,
  а показатель, которого в конкретной сдаче не было, просто оставляет пустую ячейку.
- **Кода, которого ещё нет в истории, набор не боится** — строка появится, когда появится
  первое значение.

## Что считается «лучше» и «хуже»

Рост числа сам по себе ничего не значит: для ферритина вверх — обычно хорошо, для
холестерина — обычно плохо. Поэтому сравнивается **расстояние до референсного диапазона**
(`BloodParameter.DistanceFromRange`, 0 — внутри нормы):

- расстояние уменьшилось → `Improved`;
- увеличилось → `Worsened`;
- оба измерения внутри нормы → `Stable`.

Если норма не указана или значение нечисловое — `Unknown`, и приложение молчит,
а не выдумывает оценку.

## Навигация

Shell с пятью вкладками (`dashboard`, `matrix`, `history`, `trends`, `settings`) и маршрутами
с параметрами (`testedit`, `trenddetail`, `catalog`, `catalogedit`, `viewedit`).
Все строки маршрутов — в `AppRoutes`.

Страницы и ViewModel регистрируются в DI (`ServicesRegistrator`, `ViewModelRegistrator`),
Shell разрешает их через контейнер.

## Индикатор занятости

`BaseViewModel.IsBusy` — только **вывод**: его пишет `RunAsync` и никто больше. Защёлка
от повторного запуска живёт в отдельном поле `_isRunning`.

Разделение не косметическое. `RefreshView.IsRefreshing` в MAUI по умолчанию **TwoWay**:
жест «потянуть вниз» выставляет привязанное свойство в `true` ещё до вызова команды.
Если на том же свойстве стоит защёлка, команда решает, что уже занята, выходит, не сделав
ничего, — и снять индикатор становится некому. Крутилка навсегда, экран больше не обновляется,
помогает только перезапуск приложения.

Поэтому в разметке привязка всегда с явным `Mode=OneWay`:
`IsRefreshing="{Binding IsBusy, Mode=OneWay}"`.

По той же причине `RunAsync` снимает индикатор **до** показа диалога об ошибке: зависший
системный диалог иначе заблокировал бы экран насовсем.

## Графики

Без сторонних библиотек: `TrendChartDrawable` реализует `IDrawable` и рисует полосу нормы,
ломаную и точки, окрашенные по статусу. Один и тот же класс работает и как спарклайн
в списке (`Compact = true`), и как большой график на экране показателя.

## Выгрузка

- **Таблица** (`ExportMatrixCsvAsync`) — строка на показатель, столбец на дату. Основной формат.
- **Список** (`ExportFlatCsvAsync`) — одна строка на измерение, для сводных таблиц.
- **Бэкап** (`ExportBackupAsync`) — JSON со всей историей, восстанавливается обратно.

Разделитель `;`, числа в текущей культуре, UTF-8 с BOM — так файл открывается двойным
щелчком в Excel и не ломает кириллицу. Приложение только создаёт файл; куда его отправить,
решает пользователь через системный диалог.
